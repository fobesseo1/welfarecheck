상담 신청서(`consult.html`)를 내면 구글 시트에 한 줄씩 쌓이게 하는 방법이에요. 약 10분 걸려요.
접수 주소·운영 주체 이름·보관 기간이 모두 설정되기 전에는 준비 중 안내만 나오고 개인정보 입력칸은 보이지 않아요.

로컬 개발 미리보기에서는 두 단계 신청 화면을 테스트할 수 있어요. 예시 연락처로 완료 화면까지 확인하며, 내용은 전송·저장되지 않아요. 배포 빌드에서는 접수 설정이 갖춰지기 전까지 준비 중 안내를 유지해요.

## 1. 시트 만들기 (사용자가 직접)
1. 상담용 구글 계정으로 https://sheets.google.com 에서 새 스프레드시트를 만들고 이름을 정해요. (예: 모심듀오 상담)
2. 이 시트는 **공유하지 마세요.** 상담원에게만 따로 권한을 줘요. 연락처와 (동의한 경우) 건강 관련 정보가 들어가요.

## 2. 받는 코드 넣기
1. 시트 메뉴 **확장 프로그램 → Apps Script** 를 열어요.
2. `Code.gs` 내용을 모두 지우고, 이 저장소의 `tools/consult-sheet/Code.gs` 내용을 붙여 넣고 저장해요.

## 3. 웹 앱으로 배포
1. 오른쪽 위 **배포 → 새 배포** → 유형 **웹 앱**.
2. 실행: **나**, 액세스 권한: **모든 사용자**. (누구나 신청서를 낼 수 있어야 해서예요. 시트 자체는 공개되지 않아요.)
3. 처음 한 번 구글 권한 확인 화면이 나오면 허용해요.
4. 나온 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사해요.

## 4. 사이트에 넣기
- `web/src/site.ts` 의 `consultEndpoint: ''` 에 복사한 주소를 넣어요. (Claude 에게 "이 주소로 연결해 줘"라고 주면 돼요.)
- 같은 파일에 운영 주체 이름(`company.name`)과 보관 기간(`retention`)을 함께 넣어야 신청서가 열려요. 카카오톡 채널 주소(`kakaoUrl`), 대표 전화(`phone`), 나머지 회사 정보도 정해진 값으로 넣어요.

## 접수 확인과 재시도 (2026-10-06 수정)
- 기존 웹 앱을 쓰고 있다면 최신 `Code.gs`로 교체하고 **배포 관리 → 수정 → 새 버전**으로 재배포하세요. 기존 POST만 받는 버전으로는 사이트가 접수 완료를 확인할 수 없어요.
- 사이트는 신청마다 임의 접수 ID를 붙이고, 시트에 그 ID가 저장됐는지 확인한 뒤에만 완료 화면을 보여줘요. 저장 확인이 안 되면 다시 시도할 수 있어요. 같은 ID는 서버에서도 중복 저장하지 않아요.
- 기존 시트와 새 시트 모두 마지막에 `접수 ID` 열이 추가돼요. 이 열은 상담원이 수정하지 마세요.
- 확인 요청은 ID와 성공 여부만 반환해요. 연락처·건강정보는 반환하지 않아요. [Google 공식 Content Service 문서](https://developers.google.com/apps-script/guides/content)의 JSONP 방식으로 확인해요.
- 연결 후 실제 신청 한 건이 시트에 들어오는지, 새로고침 없이 같은 신청을 재시도해도 한 행만 남는지 확인하세요. 접수 주소가 아직 없어 실제 Google 시트 연동 검증은 남아 있어요.

## 시트 모양
| 접수 시각 | 지역 | 동네 | 필요한 도움 | 직접 적은 내용 | 연락 방법 | 휴대폰 | 호칭 | 3분 체크 결과 요약 | 건강정보 동의 | 개인정보 동의 | 상태 | 담당자 | 연락한 날 | 연결한 기관 | 메모 |
- 앞쪽은 신청서가 채우고, **상태(신규 → 연락함 → 매칭 중 → 연결 완료)**부터 오른쪽은 상담원이 적어요. 이 기록이 매칭 데이터가 돼요.
- "3분 체크 결과 요약"은 보호자가 **따로 동의한 경우에만** 채워져요(건강 관련 정보는 민감정보라 별도 동의가 필요).
- 개인정보 동의 뒤에 **간병 시작 · 간병 장소 · 고른 간병인** 열이 있어요. 상담 신청에서 '간병'을 고른 경우에만 채워져요(기능 스위치 consultMore).
- **간병인등록** 탭: 간병 안내 화면의 '간병인으로 등록하기'(기능 스위치 caregiverMatch)로 들어온 신청이 따로 쌓여요. 열은 접수 시각 · 성함 · 휴대폰 · 활동 지역 · 경력 · 자격 · 가능한 곳 · 근무 형태 · 소개 · 개인정보 동의 · 상태이고, 그 뒤 확인한 사람 · 공개 동의일 · 공개 ID · 메모는 상담원이 적어요. 등록 신청만으로는 공개되지 않아요. 확인하고 공개 동의를 다시 받은 분만 `data/caregivers.json`에 넣어요.
