대상: http://localhost:5173 현재 프로젝트. 공개 배포 상태는 이번에 확인하지 않았다. 최초 검토 뒤 사용자 요청에 따라 아래 후속 수정을 적용했다.

## 후속 수정 — 사용자 요청으로 직접 반영

- 만료된 등급: 확장 돌봄 표에서도 유효기간 확인으로 표시하고 월 급여 한도액을 숨김. 현재 인정서에 시설급여가 기재된 3~5등급은 표에 반영. 미신청 예상 결과에는 실제 공단 인정과 유효한 인정서가 필요하다고 명시.
- 신청서 도우미: 65세 미만 최초 신청은 온라인 신청 버튼 대신 지사 찾기. 결과 화면에서 선택한 대리인 유형을 반영하고 모든 유형을 표시.
- 상담: 접수 주소·운영 주체 이름·보관 기간이 준비되기 전에는 개인정보 입력칸 대신 준비 중 안내. 설정된 전화·카톡은 바로 연락 버튼 표시. 접수 준비 상태에서는 홈페이지/결과도 상담 안내로 표시.
- 상담/간병인 등록: 임의 접수 ID로 실제 시트 저장을 확인한 뒤에만 완료 표시. 실패 시 재시도, 서버에서도 같은 ID 중복 저장 방지. 건강정보 전송은 별도 선택 동의 유지. 간병인 등록에 수집·이용 상세 안내 추가.
- 실제 공단 등급과 답변 예상 등급을 구분. '신뢰도 높음'을 '답변 정보 충분'으로 바꾸고 실제 정확도와 다르다고 안내.
- 상담에서 결과로 바로 돌아가기, 미완료 체크 결과는 상담 요약에 포함하지 않기, 버튼 선택 시 키보드 포커스 유지, 전송 중 입력 잠금, 간병인 ID 대신 이름 표시.
- 홈페이지 제목을 부모님 돌봄으로 확대하고 상담 안내 버튼 우선 배치. 모바일 메뉴 이름 원복과 동작 줄이기 설정 반영.
- 회귀 테스트 20개 추가, 기존 179개 유지: **13개 파일 199개 통과**. 타입 검사·배포 빌드 통과. 브라우저에서 만료 결과/준비 안내/모바일 메뉴/결과 직접 복귀/65세 미만 도우미 확인. 관리자 미리보기는 검사 후 전부 끔.
- 실제 접수 주소·전화·카톡·운영 주체·보관 기간은 미설정. Google 웹 앱 실연동 및 공개 배포는 미실행. 연결 시 최신 Code.gs 재배포 필요 (`docs/CONSULT_SHEET_SETUP.md`).

## 우선 수정/연결할 문제

### 1. [P1 / 운영 미완성] 연락처를 적고 나서야 접수 준비 중임을 알 수 있음

- 재현: 무료 상담 → 경기 → 시설 매칭 → 가상 번호 010-0000-0000 → 개인정보 동의 → 신청.
- 실제: ‘상담 접수를 준비하고 있어요. 곧 열려요.’로 끝난다. 전화·카톡 대체 버튼도 없다.
- 원인: `web/src/site.ts:6` consultEndpoint, :8 kakaoUrl, :10 phone 모두 빈 값.
- 영향: 홈페이지의 1분 신청·2~3시간 연락 약속과 실제 동작이 다르다.
- 권장: 실제 접수 저장과 운영자 확인을 연결하거나 연결 전에는 상단부터 준비 중을 안내하고 실제 직접 연락 경로를 제공한다. 접수 연결 뒤에는 시트 저장 및 운영자 확인까지 검증해야 한다.

### 2. [P1 / 확장 기능 버그] 만료 등급인데 돌봄 표에는 이용 가능

- 일반 이용자 화면에서는 careMatrix가 꺼져 있다. 기능을 켜기 전 수정할 문제다.
- 재현: 65세 이상 → 치매 없음 → 건강보험 → 현재 1등급 → 유효기간 2026-09-01 → 질문 완료 → careMatrix 미리보기.
- 실제: 위에는 유효기간 확인, 아래에는 ‘1등급 기준’, 요양원·방문요양 등 ‘이용 가능’과 월 한도가 나온다.
- 원인: `web/src/engine/result.ts:186` careGrades는 만료 상태를 반영하지 않고 현재 등급을 넘긴다. `web/src/main.ts:94`의 careView는 등급만으로 표를 만든다.
- 권장: 표에 만료 상태를 전달하고 현재 급여 이용 가능으로 표시하지 않는다. 일반 등급 정보가 필요하면 유효한 인정서 확인 이후라는 전제를 구분한다. UI 렌더까지 검증하는 회귀 테스트가 필요하다.

- 추가: 신청 자격이 없는 65세 미만 사례는 표가 이용 불가로 처리된다. 다만 실제 공단 판정이 없는 사람에게 ‘등급외 기준’이라는 제목은 오해를 줄 수 있다.

- 권장: applicant/applicant_other를 실제 양식 선택지와 대응시키고 해당 선택지가 없으면 작성 방법을 안내한다.

### 5. [P2 / 접수 연결 전 구조 문제] 저장 성공을 확인하지 않고 완료 표시

- 코드 확인 사항이며 실제 외부 저장 실패를 이번에 재현한 것은 아니다. 현재 접수 주소가 비어 있다.
- `web/src/consult.ts:166`은 no-cors fetch 뒤 응답을 읽지 않고 바로 완료로 바꾼다. 간병인 등록도 동일하다.
- Apps Script는 no-consent / bad-phone / 예외에서 ok:false를 반환하지만 클라이언트가 읽지 못한다.
- 권장: 서버 저장 성공과 접수 ID를 확인할 수 있는 방식으로 연결한다. 전송 완료를 실제 저장 성공으로 취급하지 않는다.

## 신뢰·입력 경험

- **공식 기준 표현:** 공식 항목표를 사용하지만 마지막 합산은 근사 모델이다. FAQ에는 설명이 있다. 핵심 버튼 근처에도 ‘공식 항목을 바탕으로 한 참고용 예상’처럼 차이를 밝혀야 한다.
- **신뢰도 높음:** 결과에 남아 있다(`web/src/ui/result.ts:97`). 모름 답 비율과 등급 범위 폭이며 실제 판정 적중률이 아니다. ‘답변 정보 충분/추가 확인 필요’ 등 뜻을 드러내는 표현 권장.
- **현재/예상 등급:** 현재 1등급·몸 상태 자립이면 ‘입소 가능’ 아래에 예상 등급외가 크게 나온다. 서로 다른 판단 기준이므로 계산 오류로 단정하지 않지만 보호자는 혼동한다. 현재 공단 등급을 먼저 보여주고 이번 추정을 분리한다.
- **결과 전송:** 별도 동의 기본 해제는 좋다. 결과 카드의 ‘지금 답하신 결과를 보고 상담해요’는 ‘원하시면 결과를 함께 보내실 수 있어요’로 실제 동의 처리와 맞춘다.
- **보관 기간:** ‘개인정보처리방침에서 알려드려요’만 있고 기간/방침 링크/운영 주체가 비어 있다. 실제 접수 전 구체적인 안내가 필요하다. 이번은 법적 적합성 판정이 아니다.
- **키보드:** 상담 지역을 Enter로 고르면 전체 재렌더로 포커스가 BODY로 이동한다. 선택 버튼 포커스를 유지하거나 다음 입력으로 이동시킨다.
- **메뉴:** 모바일 메뉴의 링크를 눌러 닫으면 aria-expanded=false지만 aria-label은 ‘메뉴 닫기’로 남는다(`web/src/home.ts:22`).
- **결과 복귀:** 상담의 ‘결과로 돌아가기’는 시작 화면으로 가고 ‘결과 보기’를 추가로 눌러야 한다. 답은 유지된다.
- **간병인 표시:** 선택한 간병인 상담에 이름 대신 example-cg1 같은 내부 ID가 노출된다. 이름/호칭을 표시하고 ID는 전송값으로만 쓴다.
- **간병 등록 문구:** 등록 부분의 수수료 안내와 주변 소개비 무료 안내는 서비스 범위를 나눠 운영 결정에 맞춰 설명해야 한다. 관련 법적 적합성은 이번에 검토하지 않았다.

## 디자인·사업 관점

좋은 점은 로고와 민트/차콜의 통일감, 생활 속 돌봄 사진, 쉬운 문장, 큰 모바일 버튼, 테스트에는 개인정보를 요구하지 않는 구조다. 사진은 WebP 약 42~67KB, 영상은 약 0.66/1.40MB다. 실제 느린 네트워크 성능 측정은 하지 않았다.

추천 방향:

1. 현재 첫 화면은 요양원/등급 체크 중심이다. 이미 만든 homeHub의 ‘부모님 돌봄, 어디서부터 시작할까요?’와 상황 카드가 방문요양·주간보호까지 포함하는 사업에 더 맞는다. 발견된 문제를 고친 뒤 공개를 검토한다.
2. ‘맞는 곳 찾기 무료 상담’을 체크와 동등하거나 더 중요한 버튼으로 둔다. 이미 등급이 있는 보호자는 바로 상담할 수 있게 한다.
3. 낯선 말 애니메이션 → 공감 문장/동심원 → 도움 3개 → 상세 3개로 설명이 반복된다. 특히 모바일에서는 실제 연결 방식과 선택 기준을 더 빨리 보여주면 좋다.
4. ‘딱 맞는 곳’의 기준을 구체화한다. 지역·부모님 상태·필요한 돌봄·가족 방문 거리·비용·자리 가능 여부 중 실제 상담에서 확인할 수 있는 것만 설명한다.
5. 사진 속 상담사는 예시다. 실제 운영자와 운영 주체 소개가 있어야 사람에게 연락을 맡기는 신뢰를 높일 수 있다. 사진이 실제 이용자가 아니라는 하단 안내는 이미 있다.
6. 대화의 우선 지역은 군포·안양·수원 및 서울·경기였지만 화면에는 인천까지 표시된다. 실제 운영 가능한 지역과 맞춘다.
7. 선택적 추후 정보 제공은 아직 없다. 상담 연락과 나중 정보 제공은 각각 선택할 수 있게 구성하면 앞서 말씀한 사업 의도를 반영할 수 있다.

## 검증 한계와 다음 순서

실제 시트 저장·전화·카카오 수신은 미확인이다. 공단 판정 정확도, 수형분석도 원문, 새 간병/통합지원 정책의 최신 법적 정확성은 이번에 재검증하지 않았다. 외부 공식 링크는 이동 대상만 확인했고 외부 신청을 수행하지 않았다. 실제 iOS/Android·스크린리더·느린 네트워크·동작 줄이기 설정은 별도 검증이 필요하다. 동심원 애니메이션에는 코드상 reduced-motion 분기가 없어 해당 설정에서도 동작할 가능성이 있다(실기기 재현 아님).
